Asset Notitia user guide

Getting started with the initial Jira Cloud release. Updated 23 October 2026.

Open Apps → Asset Notitia in Jira Cloud. Jira administrators manage records, services, imports, verification and comparisons. Other signed-in users with app access can read inventory and audit records and generate evidence exports. There are no OT-group or project-level read restrictions.

Create and maintain assets

Choose New asset. Enter name, IT/OT class and a matching type, accountable owner, technical custodian, criticality and lifecycle status. Select an active Jira person or a specific named team. Team labels are free text. Generic placeholders are rejected. Add location, supplier, network identifiers and lifecycle dates as needed. Decommissioning requires disposal date and evidence; Decommissioned is final.

Saving an edit checks the version opened in the form. If someone changed the record, close and reload before applying your change. Asset data and its history are saved together. History records who changed the data and when; privacy erasure may redact personal references. The detail view shows the latest 100 history entries; embedded history is retained subject to a capacity guard that refuses further writes rather than trimming silently.

Import CSV

Download the template or use Paste CSV instead. Supply required columns name, asset_class, type, owner, custodian, criticality and lifecycle_status. Each row must also have serial_number, mac_address or hostname. Owners are an exact active Jira display name, an available email address or Team: Specific Team Name. Jira privacy settings may hide emails.

Preview before confirming. Rejected rows explain what to fix. Identifiers pointing at different assets are rejected. Existing assets are updated when their identifiers match. Omitted columns preserve existing values; an explicitly blank optional column clears that value. A blank required owner is rejected. The preview is validation, not a reservation: data may change before confirmation.

Imports use batches of 25. Completed rows remain committed if later rows or batches fail. Retry the same file to update matching assets; there is no whole-file rollback. CSV only: no Excel workbook upload or interactive column mapper. Input safety caps are 10 MB and 50,000 rows; those are caps, not a verified Forge performance promise.

Verify and review

Select records in Assets and choose Mark verified. The server records actor and time and reports any individual failures. Review windows are 90 days for Safety Critical/Mission Critical, 180 for High and 365 for Medium/Low. Never-verified records age from creation; decommissioned assets are excluded.

Services and relationships

In Services, create a named service with an accountable owner. Select it and link supporting AN asset IDs. Open any asset to view service memberships, add a directed dependency or parent/child relationship, and link existing Jira issue keys. Link creation checks your permission to see the issue. Linked keys are visible to app readers; Jira still controls access when opening the issue. The app does not copy issue descriptions or attachments.

Contains links allow one parent and reject cycles. A shared row version protects the hierarchy against concurrent conflicting edits; reload after a conflict. This release supports up to 1,000 hierarchy links, subject to audit-history capacity. Connections currently query capped lists; do not advertise unrestricted graph scale.

Reconcile a source inventory

Use Reconciliation and choose the relevant IT/OT class and exact site to match the source estate. Upload or paste a CSV with name and serial_number, mac_address and/or hostname. The comparison does not change assets. Results distinguish unique matches, missing inventory, conflicting identifiers, rows with no identifiers and duplicate source rows. Coverage is uniquely matched source rows divided by all source rows, including invalid or duplicate rows. Decommissioned inventory is excluded.

The completed summary records its actor, time and counts. The CMDB-not-in-source list reflects the current inventory against saved matches. Download the comparison CSV for source-row results. Retain exports according to your organisation's policy.

Export evidence

The Evidence tab summarises active in-scope assets. Choose all assets or a service and download PDF or UTF-8 CSV. Reports identify the generating account, report ID and read interval. CSV contains all available asset fields; PDF contains a summary and compact asset appendix. Characters outside the bundled PDF font are shown as question marks with a compatibility note; use CSV to retain original text.

The export is a paged read, not a database-wide transaction snapshot. A changed row count or summary blocks completion, but edits that leave the summary unchanged may occur during the interval. Reports do not establish inventory completeness or certify compliance.

Jira actions and privacy

Automatic Jira issue creation is disabled under the approved permissions. Review the lifecycle recommendation on each asset, create any required issue in Jira yourself and link its key.

Administrators can queue irreversible personal-reference redaction in Privacy using an exact account ID and confirmation. Processing runs in batches every five minutes; verify the queue completes and reassign affected ownership. Downloads, Jira issues and Atlassian accounts are unaffected. Stored account IDs and data-age timestamps are reported to Atlassian to detect privacy changes. Administrators can review scan/report status and advance maintenance in Privacy.

Help

The final support mailbox, hours and public privacy/terms URLs require owner confirmation. Give support the screen, version, approximate time and sanitised reproduction steps. Do not send API tokens, full inventories or operational network details.
